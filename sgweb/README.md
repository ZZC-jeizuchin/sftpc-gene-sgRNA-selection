# sgRNA 设计网页

输入一段碱基 → 两个网站取数 → 三数据加权排序。

## 启动

```bash
python run_web.py            # 默认 1145 端口
python run_web.py 8080       # 换端口
```

打开 <http://127.0.0.1:1145/>

零依赖（Python 标准库 `http.server`，不需要 Flask）。

## 输入

| 项 | 说明 |
|---|---|
| **碱基序列** | ACGTN，忽略大小写与空白。CRISPOR 上限 2300 bp |
| **数据库 / 基因组** | hg38（默认）/ hg19 / mm39 / mm10 / danRer11 / dm6 / ce11 / SacCer3 |
| **PAM** | NGG（默认）/ NAG / NGA / NNGT |
| **目标位点** | 第三个数据的距离基准，默认 `22163096`（hg38，SFTPC c.218 / I73T） |

## 三个数据与权重（来自 `四个数据的定义.txt`）

| 权重 | 数据 | 来源 | 处理 |
|---|---|---|---|
| **7** | Doench '16 | 网站1 CRISPOR | **均匀映射到 0–1**（高考赋分式：按名次等距铺开，最好的=1.0，最差的=0.0，并列取平均名次） |
| **6** | CFD Spec. score | 网站1 CRISPOR | **÷100** |
| **4** | 距离 | 网站2 CHOPCHOP | `\|切点 − 22163096\|` 后**分档**：<20bp=1.0, 20–50=0.9, 50–100=0.7, 100–200=0.4, >200=0.1 |

```
总分 = (7 × d16' + 6 × cfd/100 + 4 × 距离分) / 17      归一化到 0–1
```

结果按总分降序。**不是只给第一名**：

- 页面顶部单独列出 **推荐 Top N**（默认 5 条，可在输入区或推荐区直接改，1–50）——
  每张卡片显示序列（碱基着色）、总分、分数条、Doench'16 / CFD / 距离 / 链 / PAM 起点
- 表格里 Top N 的行都高亮：第 1 名深绿标 **最佳**，第 2–N 名浅绿标 **Top 2…Top N**
- 表格默认展示**全部** 312 条，可滚动查看

## 三部分划分（负责人定的规则）

按 PAM 起点 / 20nt spacer 对齐后分成三堆：

| 部分 | 定义 | 处理 |
|---|---|---|
| **第一部分** | 两个网站**都有** | 三项正常算 |
| **第二部分** | CRISPOR 有、CHOPCHOP 没有 | 第三项补值（见下） |
| **第三部分** | CHOPCHOP 有、CRISPOR 没有 | **直接扔掉**（它们没有 Doench'16 / CFD） |

**第二部分的第三项**（`third_mode`）：

| 模式 | 行为 |
|---|---|
| `auto`（默认） | 能真算就真算，算不出来才用第一部分平均值 |
| `average` | 完全按负责人原话：一律用第一部分第三项的平均值 |
| `computed` | 只用真算值 |

> 负责人认为第二部分"没有切割位点算不出第三项"，但 **CRISPOR 也给切割位点，
> 且实测与 CHOPCHOP 完全一致（128/128）**，所以 `auto` 通常能真算。

**滚木（null）**：第一部分为空（两站完全没有共同 sgRNA）时，
第三项全部置 `null`，权重按 7:6 归一化，页面显示红色提示条。

## 第三项 = 距离分档 + 覆盖奖励

```
第三项 = 分档(|切点 − 22163096|) + (spacer 压住目标点 ? 0.1 : 0)   上限 1.0
分档: <20bp=1.0, 20-50=0.9, 50-100=0.7, 100-200=0.4, >200=0.1
```

## 两个网站的 guide 怎么合并

两个网站给的候选集不一样，按 **PAM 起点（基因组坐标）** 对齐 —— 这是唯一能跨网站对上的键。

- CRISPOR 的 `Position/Strand` 是 **PAM 左端**
- CHOPCHOP 的 `Genomic location` 是 **23mer 最左端**（正链上差 20 bp）

两者都先归一化成 PAM 起点再比对。切点 = 正链 `PAM起点−3.5`、反链 `PAM起点+5.5`。

距离**优先取 CHOPCHOP 的**（文档规定第三个数据来自第二个网站）；CHOPCHOP 没有的 guide 回退用 CRISPOR 自己算的（公式一致，已验证 128/128 完全相同）。表格最后一列标明来源。

## 接口

```
GET  /                 前端页面
GET  /api/health       健康检查
GET  /api/last         上次分析结果（刷新页面不丢，#last 可直接打开）
POST /api/analyze      {"sequence","genome","pam","target_pos"} -> 完整结果 JSON
```

## 速度

| 场景 | 耗时 |
|---|---|
| 首次（两个网站都要排队计算） | ~150 秒（1600 bp → 312 条 guide） |
| 同一个序列再跑 | **0.02 秒**（走缓存） |

## 抗失败（三级降级）

1. **某个网站挂了** → 另一个网站的数据照样出结果，橙色条提示哪个失败
2. **序列不在 SFTPC 基因座内** → 自动定位失败、拿不到基因组坐标，此时：
   - 两个网站的结果**仍然正常合并**（改用序列内坐标对齐，不会变空）
   - **距离项标记为"缺失"**，总分按剩余权重（7:6 = 13）**重新归一化**
   - 页面顶部橙色条说明原因，每行总分下面标注 `权重 13/17`
   - PAM 起点列显示 `seq:<位置>` 而不是基因组坐标
3. **只有一条数据可用** → 仍会排序，并标明权重是多少
